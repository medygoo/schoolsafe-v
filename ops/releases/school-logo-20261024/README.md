# School logo stage 1 — isolated persistent media

Runtime payload: only 12 exact source files, built over deployed Scan image `sha256:14209bb46a9ca9d31f00c9f64ad1dab4301ef8894249f9c39e6373c9373d0183`. Image qualification and 61 authenticated synthetic HTTP checks are required before release. No production school or account fixture is used.

The dedicated host directory `/opt/schoolsafe-media/school-logos` is mounted read/write **only** at `/var/www/html/assets/school-logos`. The public path serves the resized native JPEG output; code restricts image names to the active numeric school identifier. The directory is root:www-data mode 2770. Old `assets/school_logo_<id>.jpg` remains a read-only legacy fallback (never bound over all of `assets/`). Campus image then SchoolSafe branding are dashboard-only fallbacks. Do not claim a real uploaded school logo has been verified until a consenting school owner uploads one.

The controlled release creates an empty owned media directory and a root-only daily archive at `/opt/schoolsafe-media-backups` via `/etc/cron.d/schoolsafe-school-logo-media`. The media archive is included in pre-cutover backup proof. Every **future** deployment and restoration must retain exactly this bind and include this separate archive. Old release scripts expecting exactly one configuration bind are no longer safe to run unchanged. Preserve existing logo files before future image switches. Do not remove the bind or backup job by resetting the old container definition.

`deploy.py prepare` is read-only against accounts/DB and checks the exact image/legacy consumers, sessions, other services, source hashes, private DB backup, first media archive and directory ownership. `deploy.py deploy` requires a fresh backup (<15 minutes), stops the old web container and keeps it stopped under a distinct name. It does not automatically roll back over live writes. `deploy.py status` checks runtime/image/config/protected routes and dedicated logo mount; an independent verifier must also check the daily archive and verify anonymous routes cannot expose an arbitrary school logo by changing the ID in a private endpoint. No real grants, camera capture or production account mutations are part of this stage.
